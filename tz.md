# **0\. Общие принципы**

- Все новые экраны обязаны использовать Framer Motion для входа/выхода компонентов (AnimatePresence + motion.div)
- Анимации не должны блокировать интерактивность (использовать layout prop там, где размеры меняются динамически)
- Все состояния загрузки - Skeleton-компоненты, а не спиннеры
- Все состояния ошибок - EmptyState-компонент с кнопкой "Попробовать снова"
- TypeScript - строгий, никаких any
- Новые Zustand-сторы следуют существующему паттерну: persist middleware + partialize

## **2.3 PaymentMethodModal - новый компонент**

┌─────────────────────────────┐  
│ Выберите способ оплаты │  
│ │  
│ ⭐ Telegram Stars │  
│ 💳 Payme UZ │  
│ 💳 Click UZ │  
│ │  
│ \[Продолжить →\] │  
└─────────────────────────────┘

**Telegram Stars flow:**

- POST /api/v1/payments/telegram/create-invoice → получить invoiceLink
- Открыть через window.Telegram.WebApp.openInvoice(invoiceLink, callback)
- Callback: status === "paid" → POST /api/v1/payments/telegram/confirm → обновить userStore.refreshAccount()

**Payme / Click flow:**

- Если карта не привязана → показать CardInputForm
- CardInputForm: поля номер карты (маска: 0000 0000 0000 0000), срок (MM/YY)
- POST /api/v1/payment-cards/tokenize → вернёт cardToken
- Сохранить токен в paymentCardsStore
- POST /api/v1/payments/card/pay с cardToken + packageId
- Если требуется SMS-подтверждение → показать OtpModal
- POST /api/v1/payments/card/confirm с OTP кодом
- Успех → refreshAccount()

**CardInputForm требования:**

- Маска ввода номера карты
- Валидация Луна (Luhn algorithm)
- Определение платёжной системы (Visa/Mastercard) по первым цифрам
- Показывать сохранённые карты если есть (paymentCardsStore)
- Кнопка удалить карту: DELETE /api/v1/payment-cards/:id

**Состояния оплаты:**

- idle → loading → success/error
- На success: анимированный чекмарк + "Монеты зачислены: +{N}"
- На error: текст ошибки + кнопка "Попробовать снова"

## **2.4 Подписки - бесперебойная работа**

- Добавить middleware, который при переходе на защищённый роут перепроверяет статус подписки
- usageStore: все лимиты синхронизировать с сервером, не полагаться только на localStorage
- Если подписка истекла → показывать SubscribeModal с объяснением причины
- Перед показом PaywallBanner всегда делать refreshAccount() - не использовать кэш старше 5 минут

# **6\. Мультиплеер (игры PvP)**

Цель: подключить игры к серверу для режима "игрок против игрока".

Важно: это самая крупная задача, требующая серверного WebSocket. Фронтенд реализует только клиентскую часть - серверный WS должен быть согласован с бэкенд-командой заранее.

## **6.1 Инфраструктура WebSocket**

Создать src/lib/websocket/:

websocket/  
├── client.ts # WebSocket manager (singleton)  
├── events.ts # типы событий  
└── hooks/  
├── useGameRoom.ts  
└── useMatchmaking.ts

Параметры WSClient:

- Подключение: wss://api-wordzen.stnapps.com/ws?token=JWT
- Auto-reconnect с exponential backoff (1s, 2s, 4s, max 30s)
- Heartbeat ping каждые 25 секунд
- Типизированные send(event, payload) и on(event, handler)

## **6.2 Matchmaking**

┌────────────────────────────────┐  
│ 🎮 Word Rush - Мультиплеер │  
│ │  
│ ⟳ Поиск соперника... │  
│ \[0:23\] │  
│ │  
│ \[Отмена\] │  
└────────────────────────────────┘

WebSocket события:

- matchmaking:join → { gameType: "word_rush" | "daily_challenge" }
- matchmaking:found ← { roomId, opponent: UserPreview, startsIn: 3 }
- matchmaking:cancelled ← { reason: string }

## **6.3 Игровые события (Word Rush PvP)**

game:start ← { roomId, words: Word\[\], duration: 60 }  
game:answer → { roomId, wordId, answer, timestamp }  
game:score ← { userId, score, combo } // real-time  
game:end ← { winner, scores: Record&lt;userId, number&gt;, rewards }

## **6.4 UI во время PvP-игры**

- Боковая панель с очками соперника (real-time): аватар + имя + текущий счёт
- Если соперник отключился → показать OpponentDisconnectedModal + засчитать победу

## **6.5 Добавить в игры режим "Мультиплеер"**

- На странице /games добавить в карточки Word Rush и Octo Memory кнопку "🆚 Играть с другом"
- Daily Challenge - не подходит для PvP (ежедневный лимит)

# **12\. Система уровней, очков и достижений**

Данный раздел описывает полную систему мотивации: начисление рейтинговых очков за действия пользователя, 32 уровня с названиями и 40 достижений (ачивок). Цель - поддерживать долгосрочную вовлечённость без ощущения застоя.

## **12.1 Начисление очков (Рейтинговые очки)**

Очки начисляются исключительно за завершённые действия. Ни одно незаконченное действие не даёт очков.

| **Действие**                     | **Очки** |
| -------------------------------- | -------- |
| Завершение юнита                 | +5       |
| Завершение курса                 | +30      |
| Тест пройден (50-74%)            | +4       |
| Тест пройден (75-89%)            | +7       |
| Тест пройден (90-100%)           | +12      |
| Игра завершена                   | +3       |
| Игра завершена с личным рекордом | +6       |
| Ежедневное задание выполнено     | +8       |
| Бонус за streak 7 дней           | +15      |
| Бонус за streak 30 дней          | +50      |
| Помодоро завершён                | +4       |
| Первый вход в день               | +2       |

**Примечания:**

- Streak-бонусы начисляются автоматически в момент достижения серии (7 или 30 дней).
- Бонус за streak 30 дней включает в себя бонус за 7 дней - повторно за 7 дней при достижении 30 не начисляется.
- Личный рекорд в игре - лучший счёт за всё время по данному типу игры.
- Начисление атомарно и идемпотентно; все транзакции логируются для аудита.

### **12.2.1 Реализация уровней на фронтенде**

Добавить в src/lib/data/levels.ts:

export interface Level {  
level: number  
name: string  
minXp: number // суммарные очки для достижения этого уровня  
maxXp: number // суммарные очки следующего уровня (у 32 - Infinity)  
}  
<br/>export const LEVELS: Level\[\] = \[  
{ level: 1, name: 'Новичок', minXp: 0, maxXp: 50 },  
{ level: 2, name: 'Любопытный', minXp: 50, maxXp: 120 },  
// ... все 32 уровня  
{ level: 32, name: 'WordZen Master', minXp: 24480, maxXp: Infinity },  
\]  
<br/>export function getLevelByXp(xp: number): Level {  
return \[...LEVELS\].reverse().find(l => xp >= l.minXp) ?? LEVELS\[0\]  
}

Добавить в userStore:

// Вычислять реактивно из totalXp (не хранить отдельно)  
currentLevel: (state) => getLevelByXp(state.totalXp),  
levelProgress: (state) => {  
const lvl = getLevelByXp(state.totalXp)  
const range = lvl.maxXp - lvl.minXp  
return (state.totalXp - lvl.minXp) / range // 0..1  
}

## **12.4 Технические требования**

### **12.4.1 Хранение данных**

Для каждого пользователя сервер хранит:

- Суммарное количество очков (totalXp)
- Текущий уровень (вычисляется из totalXp, но кэшируется на сервере)
- Текущий streak (количество дней подряд) и дату последнего входа
- Счётчики: юнитов / курсов / тестов / игр / помодоро / ежедневных заданий
- Список полученных ачивок с датами получения
- Историю начислений очков (лог транзакций)

### **12.4.2 Начисление очков - фронтенд**

Вызывать POST /api/v1/points/award после каждого события:

// Пример вызова  
await pointsApi.award({ event: 'unit_completed', metadata: { unitId } })  
await userStore.refreshAccount() // обновить totalXp, level, coins  
<br/>// Проверить повышение уровня  
const newLevel = getLevelByXp(newTotalXp)  
if (newLevel.level > prevLevel.level) {  
showLevelUpModal(newLevel)  
}

### **12.4.3 Проверка ачивок**

- Сервер проверяет условия ачивок после каждого завершённого действия
- Проверяются только ачивки, условия которых могли измениться
- Уже полученные ачивки повторно не проверяются
- При разблокировке ачивки - сервер возвращает её в ответе на /points/award

Фронтенд обрабатывает массив unlockedAchievements из ответа:

// Ответ сервера  
interface AwardResponse {  
newXp: number  
newLevel?: Level // если уровень повысился  
unlockedAchievements?: Achievement\[\] // если есть новые ачивки  
}  
<br/>// Обработка на фронте  
for (const ach of response.unlockedAchievements ?? \[\]) {  
achievementToastQueue.push(ach) // показывать по одной  
}

### **12.4.4 Streak**

- Streak считается по числу последовательных дней с хотя бы одним ежедневным заданием
- Сброс - автоматически если пользователь не выполнил задание за текущий день (по часовому поясу)
- Streak-бонусы (+15 и +50 очков) начисляются атомарно при достижении порога
- Фронтенд отображает streak в Header/профиле, берёт значение из /account

Где отображать уровень и очки:

| **Экран**           | **Что показывать**                                             |

| Header (все экраны) | Монеты, streak, аватар с номером уровня                        |
| /profile            | Уровень + название, прогресс-бар XP, суммарные очки, 40 ачивок |
